# Data privacy

Use only resumes you are authorized to process and provide a clear notice and lawful basis appropriate to the deployment. Resume text is transmitted to Groq for inference. Groq states inference inputs/outputs are not retained by default, except that reliability and abuse monitoring may retain them up to 30 days; organizations can enable Zero Data Retention. Production startup requires an operator attestation that ZDR is enabled. Verify the current DPA, transfer safeguards, and region with counsel and the provider before use.

The application hashes raw resume content (a hash is not anonymization), encrypts resume text before graph checkpointing, and encrypts serialized graph checkpoints using a separate Fernet key. PostgreSQL must also use encrypted storage/backups and TLS. Audit events omit resume excerpts and contain only hashes and node metadata. Evaluation results contain source quotations, so checkpoint encryption and restrictive access are required. No user interface or process for access, correction, deletion, or retention requests is included; operators must implement those workflows and exercise `PostgresSaver.delete_thread` through an audited administrative tool.

Never submit resumes containing sensitive special-category data unless the deployment has confirmed necessity, legal basis, data minimization, and provider terms. Direct contact details in candidate concern quotations are rejected, but this is not a general PII detector. Key loss makes encrypted checkpoints unrecoverable; key rotation requires a controlled migration.
